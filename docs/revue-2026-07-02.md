### Conteneurs backend et RECO exécutés en root (aucun USER dans les Dockerfiles) [basse]
`backend/Dockerfile`

Ni backend/Dockerfile ni services/reco/Dockerfile ne déclarent d'utilisateur : `java -jar app.jar` et `uvicorn` tournent en root dans le conteneur. Le service RECO est particulièrement exposé : il parse des images arbitraires (PIL/OpenCV/ONNX, surface d'attaque classique de désérialisation d'images) envoyées depuis le navigateur en dev (port 8088 publié + CORS *) — une vulnérabilité dans la pile de décodage donnerait un shell root dans le conteneur.

**Piste :** backend/Dockerfile : avant ENTRYPOINT, ajouter `RUN adduser -D -u 1000 app` puis `USER app` (image alpine). services/reco/Dockerfile : ajouter `RUN useradd -r -u 1000 app && chown -R app /models /app` (ou monter le volume avec les bons droits) puis `USER app` avant CMD.
